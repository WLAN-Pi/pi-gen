# Build and release pipeline

The pipeline is `.github/workflows/build.yml`, named **WLAN Pi OS build &
release pipeline**. It runs on `ubuntu-24.04-arm`.

## Trigger

The workflow is manual. It has no `push` or `pull_request` trigger and runs
only through `workflow_dispatch`.

GitHub offers `workflow_dispatch` only for workflows that exist on the
default branch. You can dispatch against another ref, but the release job
runs only on the default branch unless the `force_release` input overrides
the guard. See [RELEASING.md](RELEASING.md).

## Inputs

| Input | Type | Required | Default | Purpose |
|---|---|---|---|---|
| `base_date` | string | no | today as `YY.MM` | Override the month used for the base version. |
| `codename` | string | yes | `theanine` | Coffee-themed release codename. |
| `repos` | choice | yes | `both` | Package cloud repos to include: `both` or `main`. |
| `build_type` | choice | yes | `dev` | `dev`, `rc`, `final`, or `point`. |
| `point_base` | string | no | none | Required for `build_type=point`; the `YY.MM` to patch. |
| `skip_full_image` | boolean | no | `false` | Build the lite image only. |
| `ab_partition` | boolean | no | `true` | Post-process the lite image for A/B partitioning. |
| `ab_root_size_mb` | string | no | `2500` | Size of each root partition in the A/B image. |
| `force_release` | boolean | no | `false` | Override the default-branch release guard. |

## Version computation

The `build-prep` job computes the version. See [VERSIONING.md](VERSIONING.md)
for the scheme.

- `base_date` defaults to the current month as `YY.MM`.
- `dev` and `rc`: `VERSION` is `YY.MM-TYPE.N`, where `N` is one greater than
  the highest existing tag for that base and type. The lookup also accepts
  the legacy `_` and `~` separators.
- `final`: `VERSION` is `YY.MM`.
- `point`: `VERSION` is `POINT_BASE.N`, where `N` is one greater than the
  highest existing tag under `POINT_BASE`.
- `FULL_VERSION` is `VERSION-CODENAME`.

The git tag is `FULL_VERSION` with no `v` prefix. The release title adds the
`v` prefix.

## Jobs

1. `build-prep`: resolves the package cloud repos and computes the version.
2. `build-image`: builds the lite and full images, generates the SBOM and
   package manifest, and uploads them as artifacts.
3. `ab-partition-image`: runs when `ab_partition=true`; converts the lite
   image to the A/B layout and validates it.
4. `release`: runs when `build-prep` and `build-image` succeed and
   `ab-partition-image` succeeds or is skipped, and when the ref is the
   default branch or `force_release=true`. Creates the GitHub release.
5. `upload-logs`: always runs; consolidates job logs.
6. `slack-workflow-status`: posts the workflow status to Slack.

## Release creation

The `release` job creates a GitHub release with `gh release create`:

- Tag: `FULL_VERSION`, for example `26.08-Cortado`.
- Title: `vFULL_VERSION`, for example `v26.08-Cortado`. When
  `skip_full_image=true`, the title ends with `[LITE ONLY]`.
- Assets: `*.img.gz`, `*.sha256`, `*.info`, and `*.sbom.xz`.
- Notes: generated by `scripts/prepare-release-notes`.

Every build type is published as a pre-release. Promotion to a stable, latest
release is manual. See [RELEASING.md](RELEASING.md).
